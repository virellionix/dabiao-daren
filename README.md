# 打标达人

一个把社媒评论与笔记转成**有原文依据、能复核、可按项目复用**的多维打标 Skill。

面向做品牌舆情、消费者洞察、媒介和数据分析的同事。AI 负责语义判断，Python 脚本负责分批、查漏行、核对原文依据、分流复核与篇级汇总。不是关键词正负面分类器，也不是已经训练好的独立模型。

**通用 Skill + 可更换项目规则包**：v1 保留默认六类品牌态度；v2 可配置情绪、信任、意图等维度的标签和边界，不把一个客户的细分码写死成通用标准。通用范围是消费者反馈，不意味着任何行业文本都已验证。

## 怎么用

将 `skills/ai-comment-labeler` 整个目录放到宿主支持的 Skills 目录，或让 AI 直接读取其 `SKILL.md`。脚本需要 Python 3.9+，不依赖外部包，不调用网络。

可以这样对 AI 说：

> 用打标达人帮我标这批评论，目标品牌是澄露。先给我看几条典型结果，拿不准的单独列出来；我确认标准后再跑剩下的。

用户旅程：

```text
给评论/笔记 + 项目规则（或选择默认口径）
       ↓
确认标签口径与少量示例 ← 有分歧则修订规则
       ↓
AI 分开判断对象、态度、情绪和行为阶段，逐项保留依据
       ↓
AI 逐字段复核 → 脚本检查 ID、字段及证据
       ↓
输出逐条/篇级候选 + 指明具体疑点的复核清单
       ↓
人工确认难例与抽查候选 → 经确认的纠错进入下个版本示例
```

### 开发演示

仓库 `examples/` 只有虚构品牌与虚构评论，不包含客户数据。以下在仓库根目录运行：

```bash
python3 skills/ai-comment-labeler/scripts/label_io.py prepare \
  --input examples/comments.jsonl --project examples/project.json --out .runs/demo
```

随后让加载了 Skill 的 AI 读取 `.runs/demo/batches/`，把逐条结果保存到 `.runs/demo/predictions/`。**prepare 不会调用 AI，也不会自动生成标签。**

```bash
python3 skills/ai-comment-labeler/scripts/label_io.py validate \
  --run .runs/demo --predictions .runs/demo/predictions \
  --out .runs/demo/checked --model current-session-unspecified
python3 -m unittest discover -s tests -v
```

输出：逐条结果 `labels.jsonl`、人工复核清单 `review.jsonl`、数量与分布 `summary.json`；v2 另有 `documents.jsonl`。核心脚本只支持 JSON/JSONL；Excel 材料可由宿主表格工具辅助整理，但没有开箱即用的 Excel/飞书接入服务。运行目录不会自动上传 GitHub。

### 使用细分标签

从 `examples/multidimensional-project.json` 创建私有项目配置，按用户资料替换维度、标签定义、单选/多选和汇总口径；完整格式见 [v2 规则包契约](skills/ai-comment-labeler/references/rule-packs.md)。可直接这样发起：

> 按这份项目规则标注笔记。态度和情绪分开，行为区分本人/他人、已做/计划/建议，按篇保留最终状态和全程出现的标签；拿不准的送复核。

离线虚构示例：

```bash
python3 skills/ai-comment-labeler/scripts/label_io.py prepare \
  --input examples/note-segments.jsonl \
  --project examples/multidimensional-project.json --out .runs/multidimensional-demo
```

AI 须单独读取冻结的 `project.json` 再标注批次，后续 validate 命令不变。只换 JSON 即可配置新的标签，无须改 Python。模板只覆盖有限标签，未覆盖的语义应标为无法判断或提出扩展建议，不强行匹配。

要检查“持续信任还是信任修复”“计划还是已执行”等边界，可使用 `examples/boundary-project.json` 与 `tests/fixtures/boundary-input.jsonl`。其内容全为虚构。试标时不要给 AI 看 `boundary-expected.json`；它用于事后对照开发者预设的边界，不是人工金标准。

项目可启用 `require_ai_review: true`，要求 AI 在交付前检查所有维度，并记录尚未解决的具体问题。标签和动作的 `validation_status: unverified` 会强制进入复核；完成指定范围的试标后可标为 `trial_passed`，但这不代表人工确认。不要通过清空复核名单来提高自动处理率。

## 当前能力与边界

- v1 明确区分 positive、negative、neutral、mixed、no_attitude、uncertain；v2 标签与维度可配置，不把骂博主默认算成骂品牌。
- 读取用户提供的标题/摘要/父评论，区分当前作者与被引用者；不抓取或虚构缺失上下文。
- 按品牌、别名、方面及多维规则复用；保留规则与输入摘要，可分批保存、接着处理未完成批次。
- 细分标签各有原文依据；行为分清本人/他人、阶段和事件前后，避免把想做、建议别人做算成自己做过。动作最强阶段与最终情绪是不同汇总规则。
- 按篇保留最终状态和全程出现集合，按配置计算实际分母；单选/多选不混算，统计结果仍是包含待复核项的候选分布。
- 校验完整 ID、合法标签、证据原文子串，保留输入顺序；异常明确失败，不拿漏行充当完成。
- v2 输出 `review_details` 和 `field_status`：疑点定位到标签维度、具体动作或来源，其他字段保留为当前原文范围内的候选；不会因为一个标签不确定就丢弃整条已知结果。全文缺失仍使整条不能验收，候选不等于确认结果。
- 对反讽、比较、混合态度、上下文不足及非 high 自评信号默认送人工复核；高置信候选仍需抽查。
- v1 有参考标签时评测总体态度的各类 precision/recall/F1 和混淆矩阵；v2 逐维人工参考评测器尚未实现。结构校验、虚构样例测试均不证明真实业务准确率。
- 人工纠错目前经人工确认更新规则/示例，不自动训练。多模型融合、Snorkel、Argilla 集成与概率校准留待真实误差证据支持后决定。

## 按用户资料做出的设计

起点是用户提供的[AI 评论打标参考对话](https://chatgpt.com/share/6aa0bf6a-7e2c-83ee-bcd4-73af0e5c4368)，不是通用情绪总结模板。对应关系：

| 资料中的重点 | 当前落点 |
|---|---|
| 先设计 Codebook | 项目规则包明确维度、定义、边界与汇总；保留六类默认口径，先小样确认 |
| Target → Aspect → Stance，先候选再检查 | 对象与方面分别记录，原文证据与简短依据并存 |
| 有限上下文、品牌/产品消歧 | title/post_summary/parent_comment + 显式品牌别名 |
| 细分情绪和行为意图 | v2 多维标签独立配置；行为另外记录 actor/stage/time_scope，不与态度强映射 |
| 允许拒绝判断 | v1 区分 no_attitude/uncertain；v2 每维配置 unknown 和复核标签，不强制正中负 |
| 人工纠错形成可用规则 | 保存纠错记录，确认后递增规则版本，测试集不回流 |
| 不只看总体准确率 | v1 各类 F1/混淆矩阵；v2 暂报分布与复核量，不冒充已完成逐维准确率评测 |

用户提供的行级 v2 底表作为本地项目的主口径，另一份 TOP50 表补充细分情绪/行为码。它们促成了连续状态段、末段口径、全程出现、行为阶段和可配置分母的实现。本次修订将混在一起的情绪、信任、决策、心理表达、内容类型与实际行为重新归位，并保留旧码映射；歧义旧码拆分后必须回看原文，不能自动翻译历史标签。具体品牌规则及原文只留在私有运行目录；两表冲突保留，不将旧 AI 结果当人工真值。未完成有效试标的类别继续复核，不以规则写完代替验证。

## 当前验证状态（2026-09-09）

- 51 项本地自动化测试通过，包含原有 28 项兼容测试和 23 项规则包测试；Skill 元数据验证通过。新增验证覆盖逐字段复核、未验证类别防绕过、局部候选保留与完整导出。
- 新增 16 条虚构边界案例的独立 AI 试标，30 项预设边界检查全部满足。2 条保留复核：1 条摘录缺上下文和转换类型，1 条命中未验证的自责标签；这不是业务准确率或生产自动处理率。
- 用户资料中的 24 条真实摘录完成了 9 个细分维度及行为阶段的独立 AI 试标，并用修订后的动作定义复核、校验。全部保留来源复核；其中 19 条品牌简称或产品线归属未确认，不据此发布目标品牌统计。原来的 59 段输入已用新规则重新 prepare，但未重标原表全部主维度。
- 本地规则包保留 63 个旧码的映射，拆分歧义后有 67 个细分标签；24 个标为摘录范围试标通过，43 个仍未验证，其中保留了原表没有已标实例的 8 个类别。旧工作簿、旧规则和旧结果均未覆盖。
- v2 独立 Agent 在虚构耳机场景完成 8 段、7 篇的标注和校验；实际分母 6 篇，资讯 1 篇排除。最终/全程状态、他人建议、事件前实际与事件后计划均保留。
- 该示例 7 段进入复核：包含信任信息不足、摘录，以及模板未覆盖的送检意图等。它验证了“不强行归类”的路径，并不说明自动处理率已达生产要求。原文中的操作命令未被执行。
- v1 曾在 12 条虚构输入上与开发 AI 预设态度一致，见 `tests/fixtures/expected_stances.jsonl`；该预期不是人工金标准，不能称为“业务准确率 100%”。
- 原始运行与模型预测留在本地 `.runs/`，不提交仓库。此次精确宿主模型 ID 未确认，标记为 `current-session-unspecified`；后续正式评测需记录精确模型版本。
- 本地项目规则与来源摘录分开保存，原始工作簿不改写。仅凭现有摘录不能验收全文分段；局部细分试标也不能冒充重新完成全部原表打标。
- 尚未验证：真实业务准确率、人工标注一致性、真实跨项目泛化和大批量耗时。需以获授权的完整原文和独立人工参考检验这些指标，不把示例测试当业务验收。
